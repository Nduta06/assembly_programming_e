# 06.asm - Push/pop in 32-bit with a look at the bytes

## What the program does
It is the 32-bit version of 05.asm. EAX = `0x11223344` and EBX = `0x1234` are
pushed, then popped back in reverse order, and the program exits with
`int 0x80`.

## Stack walkthrough
When the program started, ESP was `0xffffcda0`.

| Step | Instruction | ESP after | What happened |
|------|-------------|-----------|---------------|
| 1 | `mov eax, 0x11223344` | 0xffffcda0 | EAX loaded |
| 2 | `mov ebx, 0x1234` | 0xffffcda0 | EBX loaded |
| 3 | `push eax` | 0xffffcd9c | 0x11223344 stored |
| 4 | `push ebx` | 0xffffcd98 | 0x1234 stored on top |
| 5 | `nop` | 0xffffcd98 | where I looked at memory |
| 6 | `pop ebx` | 0xffffcd9c | EBX gets 0x1234 back |
| 7 | `pop eax` | 0xffffcda0 | EAX gets 0x11223344 back |

## How the stack works here
In 32-bit mode each push is only 4 bytes, so ESP goes down by 4 each time
(compared with 8 in 05.asm). `pop` reads the 4 bytes at ESP into the
register and moves ESP up by 4. I popped in reverse order (EBX first, then
EAX) because the stack is last in, first out.

## Observations
- ESP went cda0 to cd9c to cd98 on the pushes, and back to cda0 on the pops. That is 4 bytes each time.
- After only `push eax`, `x/2w $esp` showed `287454020  1`. The first number is 0x11223344 in decimal. The `1` was not mine. It was already on the stack before my program pushed anything.
- The registers had the same values before the pushes and after the pops because each value was popped back into its own register.
- ESP was back to `0xffffcda0` at the end, so the stack was balanced.
- The program exits with `eax = 1` and `int 0x80`, and `echo $?` gave 0.
- gdb warned "Source file is more recent than executable", which just meant I had edited the file after building it. I rebuilt it to fix that.
