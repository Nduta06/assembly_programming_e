# 02.asm - Function call and stack frame

## What the program does
`_start` calls a function called `work`. Inside `work`, space is made on the
stack for two local variables (100 and 200). They are loaded into RAX and
RBX, then the function cleans up the stack and returns. Then the program
exits.

## Stack walkthrough
When the program started, RSP was `0x7fffffffdc50` and RBP was `0x0`.

| Step | Instruction | RSP after | RBP after | What happened |
|------|-------------|-----------|-----------|---------------|
| 1 | `call work` | 0x7fffffffdc48 | 0x0 | return address pushed |
| 2 | `push rbp` | 0x7fffffffdc40 | 0x0 | old RBP (0) saved |
| 3 | `mov rbp, rsp` | 0x7fffffffdc40 | 0x7fffffffdc40 | RBP now marks my frame |
| 4 | `sub rsp, 16` | 0x7fffffffdc30 | 0x7fffffffdc40 | made room for 2 variables |
| 5 | `mov qword [rbp-8], 100` | 0x7fffffffdc30 | 0x7fffffffdc40 | 100 stored at ...dc38 |
| 6 | `mov qword [rbp-16], 200` | 0x7fffffffdc30 | 0x7fffffffdc40 | 200 stored at ...dc30 |
| 7 | `mov rax, [rbp-8]` | 0x7fffffffdc30 | 0x7fffffffdc40 | RAX = 0x64 |
| 8 | `mov rbx, [rbp-16]` | 0x7fffffffdc30 | 0x7fffffffdc40 | RBX = 0xc8 |
| 9 | `mov rsp, rbp` | 0x7fffffffdc40 | 0x7fffffffdc40 | local variables freed |
| 10 | `pop rbp` | 0x7fffffffdc48 | 0x0 | old RBP restored |
| 11 | `ret` | 0x7fffffffdc50 | 0x0 | jumped back to `_start` |

## How the stack works here
- `call` pushes the return address onto the stack. This is the address of the
  next instruction after `call`, so the CPU knows where to go back to.
- `push rbp` and `mov rbp, rsp` set up a "stack frame". RBP stays still while
  RSP is free to move. That way I can always find my variables with
  `[rbp - 8]` and `[rbp - 16]`.
- `sub rsp, 16` reserves 16 bytes for the two variables. The `mov` lines
  after that just write into that reserved space, so RSP does not change.
- To clean up, `mov rsp, rbp` frees the variables, `pop rbp` gives the old
  RBP back, and `ret` pops the return address into RIP.

## Observations
- RSP went down by 8 for `call`, 8 for `push rbp`, and 16 for `sub rsp, 16`.
  That is 32 bytes in total (0x50 - 0x30 = 0x20).
- RSP did not change on the two `mov qword` lines, because the space was already reserved.
- RBP was `0x7fffffffdc40`, which is 16 below where RSP started.
- RAX = 0x64 (100) and RBX = 0xc8 (200) after the loads.
- RBP was 0 at the start, and after `pop rbp` it went back to 0. That shows the old value was saved and restored properly.
- RSP was back at `0x7fffffffdc50` after `ret`, so the stack was balanced.
  If the cleanup was wrong, `ret` would jump to the wrong address and the program would crash.
- The program printed nothing and `echo $?` gave 0.
