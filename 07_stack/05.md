# 05.asm - Push/pop with a big value and looking at the bytes

## What the program does
RAX is loaded with `0x1122334455667788` and RBX with `0x1234`. Both are
pushed onto the stack, then popped back in reverse order, and the program
exits.

## Stack walkthrough
When the program started, RSP was `0x7fffffffdc50`.

| Step | Instruction | RSP after | What happened |
|------|-------------|-----------|---------------|
| 1 | `mov rax, 0x1122334455667788` | 0x7fffffffdc50 | RAX loaded |
| 2 | `mov rbx, 0x1234` | 0x7fffffffdc50 | RBX loaded |
| 3 | `push rax` | 0x7fffffffdc48 | big value stored |
| 4 | `push rbx` | 0x7fffffffdc40 | 0x1234 stored on top |
| 5 | `nop` | 0x7fffffffdc40 | where I looked at memory |
| 6 | `pop rbx` | 0x7fffffffdc48 | RBX gets 0x1234 back |
| 7 | `pop rax` | 0x7fffffffdc50 | RAX gets the big value back |

## How the stack works here
Each `push` moves RSP down by 8 and writes the 8-byte register there. Each
`pop` reads 8 bytes from RSP into a register and moves RSP up by 8. Because
the stack is last in, first out, I had to pop in the opposite order of the
pushes: RBX was pushed last, so it is popped first.

## Observations
- RSP went from dc50 to dc48 to dc40 on the pushes, and back to dc50 on the pops. That is 16 bytes down and 16 bytes up.
- Each push used a full 8 bytes, even for the small value 0x1234. The rest of the slot was filled with zeros.
- The registers had the same values before the pushes and after the pops
  (RAX = 0x1122334455667788, RBX = 0x1234), because I popped them back into the same registers they came from. Since RAX and RBX did not change when pushed, it also shows `push` only copies the value.
- RAX later became 0x3c (60) because of `mov rax, 60` for the exit.
- The program printed nothing and `echo $?` gave 0.
