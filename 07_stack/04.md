# 04.asm - Function call and stack frame (32-bit)

## What the program does
It is the 32-bit version of 02.asm. `_start` calls `work`. Inside `work`,
room is made for two local variales (100 and 200), they are loaded into EAX
and EBX, and the function cleans up and returns. The program exits with
`int 0x80`.

## Stack walkthrough
When the program started, ESP was `0xffffcda0` and EBP was `0x0`.

| Step | Instruction | ESP after | EBP after | What happened |
|------|-------------|-----------|-----------|---------------|
| 1 | `call work` | 0xffffcd9c | 0x0 | return address pushed |
| 2 | `push ebp` | 0xffffcd98 | 0x0 | old EBP (0) saved |
| 3 | `mov ebp, esp` | 0xffffcd98 | 0xffffcd98 | EBP marks my frame |
| 4 | `sub esp, 8` | 0xffffcd90 | 0xffffcd98 | room for 2 variables |
| 5 | `mov dword [ebp-4], 100` | 0xffffcd90 | 0xffffcd98 | 100 stored at ...cd94 |
| 6 | `mov dword [ebp-8], 200` | 0xffffcd90 | 0xffffcd98 | 200 stored at ...cd90 |
| 7 | `mov eax, [ebp-4]` | 0xffffcd90 | 0xffffcd98 | EAX = 0x64 |
| 8 | `mov ebx, [ebp-8]` | 0xffffcd90 | 0xffffcd98 | EBX = 0xc8 |
| 9 | `mov esp, ebp` | 0xffffcd98 | 0xffffcd98 | locals freed |
| 10 | `pop ebp` | 0xffffcd9c | 0x0 | old EBP restored |
| 11 | `ret` | 0xffffcda0 | 0x0 | back in `_start` |

## How the stack works here
It works the same way as the 64-bit version in 02.asm, but registers are 32
bits (4 bytes) wide, so everything on the stack is 4 bytes. ESP changes by 4
for each `call`, `push` and `pop`. I also used `dword` and `[ebp-4]`,
`[ebp-8]` instead of `qword` and `[rbp-8]`, `[rbp-16]`.

- `call` pushes the return address.
- `push ebp` and `mov ebp, esp` set up the frame.
- `sub esp, 8` reserves space for two 4-byte variables.
- `mov esp, ebp`, `pop ebp` and `ret` clean up and return.

## Observations
- ESP moved in steps of 4 (cda0 to cd9c to cd98), compared with steps of 8
  in 02.asm.
- `sub esp, 8` moved ESP down by 8 (cd98 to cd90).
- The whole frame used 16 bytes (4 return address + 4 saved EBP + 8 locals),
  compared with 32 bytes in the 64-bit version.
- EAX = 0x64 (100) and EBX = 0xc8 (200) after the loads.
- EBP was 0 at the start and went back to 0 after `pop ebp`.
- ESP was back to `0xffffcda0` after `ret`, so the stack was balanced.
- The exit uses `eax = 1` and `int 0x80`. EBX became 0 from `xor ebx, ebx`
  just before the exit, so the exit code is 0.
